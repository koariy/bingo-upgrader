# Финальный клиент 1.0.0

## Общие компоненты

`Ui` хранит palette/Identifiers и nine-slice, слот, паттерн, tooltip. `ThemeButton`
поддерживает мышь/клавиатуру, hover по времени и короткую отдачу. `ThemeSlider`
использует стандартную input-логику AbstractSliderButton с собственной отрисовкой.
`ThemeToast` рисует модульные уведомления; сообщения одной категории обновляют
существующий toast, чтобы серия клеток не создавала длинную очередь.

`CanvasScreen` рисует в логическом пространстве, затем применяет единый
CanvasLayout к графике и обратное преобразование к MouseButtonEvent/scroll.
Апгрейдер/выбор цели — 440×365; карточка бинго — 420×350; настройки — 420×330.
Фон появляется за 220 ms, закрытие — за 150 ms. Фокус/клавиатура основаны на
обычных Minecraft widgets, без отдельного игрового контейнера на клиенте.

HUD использует экранные GUI-координаты; relative x/y и scale сохраняются локально,
ограничиваются краями после resize. Board и общий слот переиспользуются в HUD.

## Апгрейдер

ClientUpgrader открывает UpgraderScreen по Opened, принимает серверный
UpgradeCatalog с разрешёнными **обычными** целями, edge/min/max/cap и preview TTL.
Части старого протокола сохранены, к PreviewRequest/Quoted/Rejected добавлен
requestId. Запоздалый ответ не может активировать кнопку для нового выбора.
При обновлении таблицы экран пересчитывает отображение и запрашивает превью.

Выбор — Map<inventorySlot,count>. Клик меняет только map; клиент никогда не
вызывает inventory.setItem/add для этой операции. При изменении реального
инвентаря количества ограничиваются текущими стопками и старое preview теряется.
На запросах debounce 180 ms; молча ограниченный сервером запрос повторяется
через 2 s. Актуальное preview автоматически освежается примерно на 65% TTL;
пока оно пересчитывается, кнопка попытки отключена.

Каталог строится на сервере по UpgradePolicy; поиск/категории/тиры/сортировка
кэшируются на клиенте. «Доступно по ценности» использует серверные коэффициенты
и текущую выбранную сумму для приближённого фильтра. Он не заменяет серверное
разрешение попытки. Unknown-цели скрыты сервером по умолчанию; их разрешение задаёт allowUnknownTargets.
Тиры соответствуют settings.tiers бинго; категории определяются
по BlockItem, прочности и food/consumable components, остальные — материалы.

`UpgradeAnimation` начинает вращение только после Result. Траектория — шесть
оборотов + landing, smootherstep с нулевой скоростью в начале/конце, 3.8 s.
Client tick ставит звуковые щелчки, а графика интерполируется по System.nanoTime.
В конце — звук и ThemeToast. Контроллер работает и при закрытом экране, поэтому
выдача не зависит от того, досмотрел ли игрок визуальный эффект.

Кольцо кэшируется атласом с шагом 1°. Точный процент остаётся серверным;
для очень маленьких зон видимый сектор имеет минимум 1°, а перед самой единицей
остаётся минимум 1° зоны неудачи. Только **визуальная** координата landing
переносится внутрь соответствующего отображаемого сектора, чтобы округление
пикселей не показывало «победу снаружи». Исход/шанс/выдача не меняются. Эта
геометрическая погрешность не участвует в RNG или балансе.

Успех: радиальный green flash, 28 частиц, иконка летит по дуге в целевой слот,
потом остаётся статическая выбранная цель. Неудача: red flash и распад частиц
из панели вложений. Вращение имеет небольшой затухающий detent, строго нулевой
в конечной точке. Сглаженный процент использует экспоненциальную интерполяцию,
результат за одинаковое время совпадает при 60 и 144 FPS (проверяется тестом).

## Бинго

ClientBingo обновляет BingoVisuals на разнице персональных масок. Для новой
отметки хранится только timestamp, не растущий список объектов. Галочка
масштабируется, зелёная заливка затухает, новая готовая линия пульсирует 2 s.
При первом JOIN существующие отметки не проигрываются как новые награды.
BingoBoard использует кэш ItemStack, создаваемый только при смене карточки.
Карточка/настройки/табло используют CanvasScreen и ThemeButton, уведомления —
тот же ThemeToast, что апгрейдер. Серверная логика из части 4 не дублируется клиентом.

## Ограничения и настройка

Собственного TTF и OGG нет: встроенный кириллический Minecraft font и aliases
к стандартным sound events — готовые ресурсы, которые можно заменить.
Экран не является контейнером: перетаскивание реальных предметов не требуется;
поддерживаются клики/Shift-клики выбора и slider, server inventory остаётся
единственным источником предметов. В Creative/Spectator экономика запрещена.

Физические FPS зависят от GPU/модпака/мира. Код не создаёт текстуры, не сортирует
полный каталог и не пересчитывает RNG в render. Изменяемая текстовая строка
процента и несколько matrix операций на кадр остаются обычной нагрузкой GUI.
