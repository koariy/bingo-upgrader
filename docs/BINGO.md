# Бинго — часть 4

Мод **1.0.0**, Minecraft **26.2**, Java **25**, Fabric Loader **0.20.1**,
Fabric API **0.161.0+26.2**. Зависимости и команды предыдущих частей сохранены.

## Быстрый запуск

```text
/bingo settings mode competitive
/bingo settings goal line
/bingo start
/bingo card
/bingo scoreboard
/bingo stop
/bingo restart
/bingo reset
```

`/bingo` открывает карточку. `/bingo settings` открывает простой экран настроек.
Его общие ThemeButton позволяют выбрать режим/победу, бесплатный центр, сдачу предметов,
изменить лимит времени, запустить/остановить/сбросить/перезапустить матч.
Кнопки управления доступны только уполномоченному игроку; проверка повторяется
на сервере. Основные настройки нельзя менять командами/кнопками во время матча.

Режимы:

- **solo**: участвует только запускающий игрок; для console start нужен другой режим.
- **coop**: общая карточка и общий прогресс; уже отмеченную клетку другой игрок
  повторно не сдаёт. Все участники получают командную победу.
- **competitive**: у всех одна карточка, прогресс отдельный. Матч заканчивается
  при первом серверном обнаружении выполненного условия. События одного тика
  разрешаются в порядке обработки сервером, победитель один.

Участники фиксируются при старте: живые online-игроки Survival/Adventure,
максимум 256. Поздний вход — наблюдение до следующего матча. Переподключившийся
участник сохраняет своё место и прогресс по UUID. В Creative/Spectator отметки
не начисляются. Offline-участники остаются в таблице. Уже имеющиеся предметы
засчитываются после старта; это режим «иметь», а не доказательство новой добычи.

`stop` сохраняет карточку/прогресс, но завершает матч без победы. `reset` очищает
его. `restart` создаёт новую случайную карточку и новый состав участников.
Если генерация или проверка состава не удалась, предыдущий матч не заменяется.

## Отметки и победа

25 уникальных ID предметов, по одному предмету на клетку. Компоненты/зачарования
не являются отдельными целями. Центральная бесплатная клетка — индекс 12.
Условия: `line`, `two_lines`, `full`. Проверяются 5 горизонталей, 5 вертикалей
и обе диагонали; при двух линиях пересечение разрешено. Бесплатная клетка
участвует в линиях, но не увеличивает число добытых клеток в табло.

Инвентарь проверяется на сервере после подбора (`ItemEntity.playerTouch`),
обычного крафта (`ResultSlot.onTake`), непосредственно после commit апгрейдера,
а также каждый server tick для сундуков, команд, плавки, модовых способов выдачи
и перемещения вещей. Учитываются слоты Player Inventory, включая броню/вторую
руку, если они представлены его контейнером; вещи в сундуках, на земле и на
курсоре не считаются. Обычный крафт на курсор засчитывается после перемещения
результата в инвентарь. Периодическая проверка имеет задержку до одного тика.

При `surrender=false` предметы остаются у игрока, отметки необратимы до reset.
При `surrender=true` сервер удаляет ровно одну штуку за каждую новую клетку;
повторная проверка не тратит предмет снова. Сдаётся сам ItemStack, поэтому
дополнительные компоненты и содержимое контейнера также расходуются вместе
с ним. Отдельной кнопки сдачи в этой части нет — режим сдачи автоматический.
При выигрыше апгрейдера предмет может сразу быть сдан в бинго до следующего кадра.

В кооперативе табло показывает личный вклад в клетки; линию получает игрок,
чья последняя отметка её завершила. В остальных режимах линии считаются по
личной маске. Сортировка: линии, затем клетки, затем UUID при равенстве.
Снимок после отметок отправляется в конце текущего серверного тика.

## Таймер и сохранение

Лимит по умолчанию 30 минут. `timeLimitSeconds=0` — без ограничения, таймер
показывает прошедшее время. В остальных случаях показывает оставшееся время.
Считаются **серверные тики**: при выключенном сервере время не расходуется,
при низком TPS матч длится дольше по настенным часам. Когда достигнут лимит,
матч становится `timeout`, дальнейших отметок нет.

В overworld SavedData `bingo_upgrader:bingo_match` хранятся schemaVersion,
matchId, frozen rules, карточка, состояние, elapsedTicks, общий прогресс,
индивидуальные маски/имена/вклад, победители и ревизии. Модель сериализуется
через Gson/Codec.PASSTHROUGH в обычную структуру NBT, а не одну большую строку.
После штатного сохранения/перезапуска матч продолжается с прежними участниками,
карточкой и временем. Отметки/управление помечают SavedData dirty сразу,
таймер — каждую секунду. Дисковая атомарность следует сохранению мира Minecraft.
Проверки при загрузке отвергают неправильные маски, размеры и неизвестную схему.

## Конфиг

`config/bingoupgrader/bingo.json` создаётся автоматически:

```json
{
  "mode": "competitive",
  "goal": "line",
  "freeCenter": false,
  "surrender": false,
  "timeLimitSeconds": 1800,
  "tiers": [
    {"name":"easy",   "min":0,    "max":10,            "count":10},
    {"name":"medium", "min":10,   "max":100,           "count":10},
    {"name":"hard",   "min":100,  "max":1000,          "count":4},
    {"name":"rare",   "min":1000, "max":1000000000000, "count":1}
  ],
  "managers": [],
  "blacklist": []
}
```

Каждый тир — диапазон `[min,max)`. Четыре диапазона не пересекаются, count >=0,
сумма count равна 25 без free center или 24 с ним. При переключении центра
через GUI/команду count первого тира автоматически уменьшается/увеличивается
на единицу. Для иных распределений редактировать JSON, затем
`/bingo settings reload`. Отсутствующие поля получают defaults; явно заданные
списки/карты заменяют поле целиком. Разрешены лимит 0..604800 секунд,
до 256 managers UUID и до 1024 blacklist ID; файл до 1 MiB.

Пул берётся из **серверной таблицы ценностей**: без unknown и blacklist,
с учётом дополнительных ограничений апгрейдера и enabled features. Тиры используют
цену обычной одной штуки; динамические enchant/potion компоненты не создают
отдельных целей. Применяются datapack-рецепты и теги через готовый ValueService.
Если в тире не хватает допустимых уникальных предметов, старт отклоняется
с подробностью в серверном журнале, другие тиры автоматически не подменяют его.
Настройки фиксируются в матче; reload JSON влияет на следующие матчи,
а текущая карточка, правила и прогресс сохраняются.

Управление: permission `COMMANDS_GAMEMASTER` (обычно OP 2) либо UUID в managers:

```json
"managers": ["12345678-1234-1234-1234-123456789abc"]
```

Имена не используются для авторизации. `start/stop/reset/restart`, изменение
настроек и reload защищены. `card/scoreboard` и просмотр settings доступны
всем, чтобы участникам не требовались права оператора. Полный JSON редактируется
на сервере; C2S-пакет не может менять managers, blacklist или произвольный файл.

## Простой клиент

- Карточка: 5×5 иконок, tooltip предмета, зелёные отметки/галочка, золотая рамка
  клеток готовых линий, статус и таймер.
- Табло: сортированный список с постраничной навигацией.
- Настройки: общие ThemeButton; controls обновляются после ответа сервера.
- Уведомления: локализованные сообщения в чат и общие ThemeToast, объединяющие быстрые сообщения одной категории.
- HUD по умолчанию включён. Settings → «Настроить HUD»: перетаскивание левой кнопкой,
  колесо меняет масштаб; Done/Esc сохраняют положение. Координаты относительные,
  ограничиваются текущим экраном; F1 скрывает HUD. Иконки кэшируются до смены карточки.

Локальные настройки: `config/bingoupgrader/bingo-client.json`:

```json
{"hudEnabled":true,"hudX":0.02,"hudY":0.08,"hudScale":1.0}
```

Положение 0..1; масштаб 0.5..2.5. Сервер не управляет этими предпочтениями.
Все новые надписи находятся в lang-файлах ru_ru/en_us. Игровые экраны не ставят
сервер на паузу. Полная тема, анимации линий и собственные тосты реализованы в 1.0.0; см. CLIENT.md.

## Сеть и API

`BingoPackets.Control` (C2S): matchId/controlRevision, action/field/value.
Сервер проверяет права, допустимые поля, типы значений, состояние матча и
актуальность управления, ограничивает запросы интервалом 150 мс на UUID.
Клиент не может отправить клетку, прогресс, победителя или время.

`BingoPackets.Snapshot` (S2C): персональный BingoView, settings без managers,
карточка, маска, отсортированное табло, победители, canManage/participant;
optional screen открывает card/settings/scoreboard. Полный снимок отправляется
при JOIN, после изменения и раз в секунду для времени. Предел 262144 символа
JSON / large payload 1 MiB; имена и команды отдельно ограничены.
`Notice` (S2C) передаёт тип уведомления, имя и количество. При disconnect клиент
очищает кэш. Snapshot нельзя использовать как серверное основание для отметок.

Основные классы и методы:

| Пакет | Классы / назначение |
| --- | --- |
| common.config | BingoConfig, Tier, validate() |
| common.bingo | BingoState, BingoView, BingoRules, BingoClock, BingoScores, BingoJson |
| server.bingo | BingoService, BingoProgress, BingoGenerator, BingoSavedData, BingoConfigStore, BingoCommands |
| server.bingo.mixin | ItemPickupMixin, CraftingMixin |
| common.network | BingoPackets: Control, Snapshot, Notice |
| server.network | BingoNetworking: sync(player,screen), broadcast(server), event(...) |
| client.network | ClientBingo: view(), items(), action(...), setting(...) |
| client.bingo | BingoClientConfig, BingoBoard, BingoCardScreen, BingoSettingsScreen, BingoHudEditor |

Серверные методы после SERVER_STARTED, на серверном потоке:

```java
BingoService bingo = BingoService.get(server);
bingo.startMatch(source); // permission check, полноценная генерация перед заменой
bingo.stopMatch(source);
bingo.reset(source);
bingo.restart(source);
bingo.setting(source, "goal", "two_lines");
BingoView snapshot = bingo.view(player);
BingoService.inventoryChanged(player); // hook после завершённой выдачи предметов
```

`tick()` продвигает время и проверяет online-участников; регистрируется один раз
в END_SERVER_TICK. `flush()` рассылает накопленные изменения. `reload()` читает
конфиг, не заменяя текущие rules. `canManage(source)` проверяет полномочия.
`BingoProgress.claim(state,uuid,name,container)` — детерминированный серверный
переход, используемый сервисом и тестами, возвращает Delta(cells,lines,won).
Не вызывать напрямую из клиента или для произвольного контейнера в игровом коде.

В апгрейдере добавлен явный hook после inventory commit, а также публичный
`UpgradeService.isAllowedItem(stack)` для генератора. При загрузке/остановке
мира сервисы создаются/удаляются раздельно для каждого MinecraftServer.

## Проверка и актуальные API

`./gradlew build` запускает предыдущие проверки, 12 млн симуляций апгрейдера
и проверки бинго: 100 карточек по тирам, уникальность/free center, нехватка пула,
12 линий/диагонали, все условия победы, независимый прогресс соревнования,
общие клетки и вклад coop, однократная сдача, поздний наблюдатель, предмет-приз,
таймер/таймаут/нулевой лимит, сохранение в JSON и реальном NbtOps, сетевые codecs.

Компиляция common/server/client и dedicated Fabric bootstrap до EULA проверены.
Финальный клиент 1.0.0 проверен в реальном одиночном мире: карточка, отметки,
приз апгрейдера, сохранение/перезапуск, русские экраны и HUD. Полная отдельная
мультиплеерная сессия не проводилась; EULA dedicated server автоматически не принималась.

API 26.2: `Screen.extractRenderState(GuiGraphicsExtractor,...)`, `g.item/text`,
`MouseButtonEvent`, `Minecraft.gui.setScreen`, `Minecraft.gui.hud.isHidden`,
`HudElementRegistry`, `SystemToast`, `SavedDataType`/`SavedDataStorage`,
typed payload registries, ServerTickEvents. Сигнатуры сверены по закреплённым JAR
через javap; это не старые render/GuiGraphics или Options.hideGui из 1.21.
Документация 26.2:

- https://docs.fabricmc.net/develop/rendering/gui/custom-screens
- https://docs.fabricmc.net/develop/rendering/hud
- https://docs.fabricmc.net/develop/networking

Два точечных mixin используются потому, что закреплённый Fabric API не предоставляет
общего callback для всех pickup/crafting выдач. Дополнительно остаётся tick scan;
никакие сетевые клиентские сообщения не засчитывают прогресс.

Итог проверки 0.4.0: `BUILD SUCCESSFUL`; 774 проверки бинго + 23 ценностей +
85 апгрейдера (882 суммарно), 100 генераций карточек и 12 млн симуляций.
NBT round-trip проверяет оба флага freeCenter/surrender с преобразованием byte ↔ boolean.

Сведения о тестах промежуточной 0.4.0 выше сохранены как история; актуальная
проверка финальной 1.0.0 — в VERIFICATION.md.

## Обновление 1.0.1: сложности и клавиша таблицы

Сложность выбирается в `/bingo settings` кнопкой «Сложность» или командой
`/bingo settings difficulty easy|normal|hard|expert`. Активный матч сначала
остановить; затем применить настройки и запустить `/bingo restart`.

| Сложность | Лёгкие | Средние | Сложные | Редкие |
| --- | --- | --- | --- | --- |
| easy — легко | 20 | 5 | 0 | 0 |
| normal — обычно | 10 | 10 | 4 | 1 |
| hard — сложно | 5 | 10 | 8 | 2 |
| expert — эксперт | 2 | 6 | 12 | 5 |

Бесплатный центр заменяет одну лёгкую клетку. Цена определяет тир; в лёгком
пресете дополнительно исключены известные vanilla-материалы Незера/Энда и
другие поздние группы, даже если их цена низкая (например end_stone и warped_planks).
Модовые предметы определяются по настроенной ценности; для нестандартных
измерений/способов добычи использовать blacklist и границы тиров.

В JSON `difficulty` применяет выбранное распределение при загрузке. Для своих
count выставить `"difficulty":"custom"`. Старые JSON без difficulty сохраняют
свои count; новые пресеты не меняют границы ценностей, заданные в tiers.
Старые сохранённые матчи продолжаются со своими замороженными правилами.

**B** по умолчанию скрывает/показывает HUD-таблицу в игровом мире. Переназначение:
Настройки Minecraft → Управление → Назначение клавиш → «Бинго и апгрейдер» →
«Скрыть/показать таблицу бинго». В настройках бинго есть прямая кнопка перехода
к назначению клавиш. При вводе текста в меню/чат бинд не срабатывает.

Скрытие/появление занимает 280 мс: сдвиг, масштабирование и сворачивание по
smootherstep. Повторное нажатие меняет направление из текущей точки без скачка.
Настройка видимости сохраняется локально и не останавливает прогресс матча.

## Обновление 1.0.2

Стандартный бинд таблицы — **Tab**, вместо B из 1.0.1. Сохранённые назначения
Minecraft не сбрасываются: при обновлении выставьте Tab вручную в управлении.
У Tab также есть vanilla-функция списка игроков; её назначение можно изменить.
